# 모델 선정 기록

## 시험한 모델

| 모델 | 위치 | 데이터셋 | 상태 |
|---|---|---|---|
| MobileNetV4 + Faster R-CNN | `archive/mobilenetv4/` | construction-ppe, safety-Helmet-Reflective-Jacket, SH17 | 사용 중단, 기록용 보관 |
| YOLOv8n (A단계) | `yolo_test/` | construction-ppe, 12클래스 | 비교 실험 |
| YOLOv8n ppe3 (B~E단계) | `yolo_ppe3/` (`yolo-ppe3` 브랜치) | ppe3, 3클래스 | 채택 |

MobileNetV4를 쓰지 않기로 한 이유:

속도: 실시간 판정에 필요한 프레임이 나오지 않았다. 2단계 탐지 구조(Faster R-CNN)라서 1단계 탐지기인 YOLO보다 느리다.
판정 안정성: 같은 장면에서도 박스와 판정이 프레임마다 크게 흔들렸다.
오인식: 안전모를 쓰지 않아도 헬멧으로, 안전조끼를 입지 않아도 입은 것으로 인식하는 경우가 있었다. 
출입 통제에서 가장 위험한 오류는 미착용자를 통과시키는 것이라서, 이 문제를 치명적으로 판단했다.

측정 수치는 기록하지 않았다. 두 모델은 학습 데이터셋이 서로 달라서(MobileNetV4: construction-ppe 등, YOLO 채택본: ppe3) 위 문제 중 일부는 데이터셋 차이에서 왔을 수 있다.

## YOLO 실험 경과

수치는 `yolo_ppe3/README.md`에서 옮겼다. B~E는 같은 test 사진 2,751장으로 비교했고, A는 데이터셋이 달라 직접 비교할 수 없다. FPS는 1280×720 화면 기준이다.

| 단계 | 바꾼 것 | mAP@0.5 | head recall | FPS (PC CPU) |
|---|---|---|---|---|
| A | YOLOv8n, construction-ppe 12클래스, 320px | 0.633 | 측정 안 함 | 114 |
| B | ppe3 3클래스로 데이터셋 교체, 320px | 0.883 | 0.759 | 114 |
| C | head 이미지 3배 오버샘플링 | 0.892 | 0.818 | 114 |
| D | 640px 학습, 480px 추론 | 0.924 | 0.860 | 70 |
| E (채택) | 50 epochs | 0.930 | 0.851 | 70 |
| 배포용 | NCNN, 16:9 입력 480×288 | E와 거의 같음 | E와 거의 같음 | 96 |

라즈베리파이 FPS는 아직 어느 단계도 측정하지 않았다. INT8 양자화도 하지 않았다.
